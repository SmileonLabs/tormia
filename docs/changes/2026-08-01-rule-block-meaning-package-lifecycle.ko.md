# 규칙 블록과 의미 패키지 수명주기

## 결정

규칙 할당과 삭제는 Authority의 `bindingId`를 식별자로 사용한다. Unity는 온라인 의미 상태를 먼저 수정하지 않는다. Authority가 원자적 추가, 일부 바인딩 삭제, 마지막 패키지 종료, 복원, 리비전 기반 출처를 소유한다.

## 생산 흐름

`빠른 설정 -> 선언형 의미 패키지 -> Authority 검증 -> 소유권이 기록된 트리플/바인딩 -> 출처 포함 프로젝션 -> Unity 편집 UI`

## 활성·제거 검증

- 행동 패키지 추가에는 게시된 소유 규칙 블록이 최소 하나 필요하며 선언된 작성 트리플과 원자적으로 생성된다.
- 바인딩 하나를 삭제하면 해당 식별자와 그 `RuleBound` 결과만 철회된다.
- 마지막 소유 바인딩을 삭제하면 패키지가 종료되고 소유 정규·타입 트리플은 철회되지만 독립 기여는 남는다.
- 명령 실패 시 Unity의 기존 프로젝션은 변경되지 않는다.

## 기존 기여 채택 순서 보정

소유자가 없는 정확히 일치하는 카탈로그 기여를 교체 대상 철회 전에 먼저 찾아 채택 대상으로 예약한다. 이 데이터는 패키지 소유가 되며 displaced 기준 원장에 기록되지 않는다. 일회성 출처 보정은 과거 처리 순서 오류로 복원됐음이 증명되는 행만 철회하고, 내구 액션 상태와 독립 기여는 유지한다.
