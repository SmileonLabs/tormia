# 지속형 Unity MCP 전송

## 요약

- **날짜:** 2026-07-28
- **담당:** TOV 개발 하네스
- **상태:** 검증
- **관련 요청:** 연속된 Unity 에디터 작업 중 MCP가 반복해서 연결 해제로 보이는 문제

## 의도

Unity 스크립트 컴파일과 어셈블리 리로드 뒤에도 Codex가 자동으로 다시 연결되어,
사용자가 Unity를 반복 재시작하거나 Start Session을 다시 누르지 않게 합니다.

## 결정과 경계

로컬 개발은 `http://127.0.0.1:8080/mcp`의 단일 MCP for Unity Streamable HTTP
서버를 사용합니다. 서버는 Unity 에디터 도메인 밖에서 계속 실행되고, Unity는
리로드 뒤 HTTP/WebSocket 브리지로 다시 접속합니다. Codex는 작업마다 별도
stdio Unity 서버를 시작하지 않습니다.

이 전송 계층은 온톨로지 의미, 계정 상태, 영속 월드 명령, 게임 규칙, 물리,
표현 결정을 소유하면 안 됩니다.

## 온톨로지 표현

없습니다. 개발 도구 전송 변경이므로 canonical 용어, 트리플, 프로필, 룰블록,
규칙 결과를 추가하지 않습니다.

## 검증

| 경우 | 기대 결과 | 증거 |
| --- | --- | --- |
| 활성 / 추가 | HTTP 서버가 정상이고 `tormia` Unity 인스턴스가 연결됨 | `scripts/verify-unity-mcp.ps1` |
| 비활성 / 제거 | 서버·Unity 인스턴스가 없거나 Codex가 stdio 설정이면 명시적으로 실패 | `scripts/verify-unity-mcp.ps1` 음성 검사 |
| 회귀 / 경계 | 강제 Unity 스크립트 리로드 중 인스턴스가 잠시 사라진 뒤 자동 복구 | 2026-07-28 측정: 수동 클릭 없이 10.7초에 복구 |

## 성능과 멀티플레이 영향

로컬 HTTP 서버 하나가 지속형 개발 프로세스로 실행됩니다. 데이터베이스 쓰기,
플레이어 대상 네트워크 fan-out, 월드 이벤트, 멀티플레이 권한 변경은 없습니다.
