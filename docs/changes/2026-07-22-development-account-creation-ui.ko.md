# 비밀번호 인증 계정 진입

## 결정

씬에 배치된 진입 흐름은 이제 **로그인** 또는 **계정 만들기**로 시작합니다.
가입과 로그인은 World Authority 인증 API를 호출하고 불투명 Bearer 세션을 받습니다.
기존 자동 개발 계정, `/v1/dev/users`, 호출자가 지정하는 `X-Tormia-User-Id`
권한 경로는 제거했습니다.

## 경계

- 비밀번호는 인증 데이터이며 계정 프로필 트리플이나 월드 Fact가 아닙니다.
- Authority는 비밀번호를 PBKDF2로 해시하고, 원본 세션 토큰은 한 번만 반환하며 서버에는 토큰 해시만 저장합니다.
- Unity는 REST와 SignalR 요청에 Bearer 세션을 붙입니다. PlayerPrefs 토큰 저장은 현재 데스크톱 개발 슬라이스에만 허용하며 운영 전 플랫폼 보안 저장소로 교체합니다.
- 가입 성공 시 계정 소유 캐릭터 생성으로, 기존 계정 로그인 성공 시 캐릭터 선택으로 이동합니다.

## 활성·비활성 근거

- 활성: 가입, 계정 대시보드 조회, 캐릭터·월드 생성, 재로그인, Bearer 세션 기반 SignalR negotiate가 성공합니다.
- 비활성: 누락·폐기 세션은 인증되지 않고, 잘못된 비밀번호와 중복 가입은 거부되며 `/v1/dev/users`는 존재하지 않습니다.
- Unity UI smoke에서 새 계정을 가입하고 Bearer 세션으로 빈 대시보드를 읽은 뒤 캐릭터 생성 화면으로 이동했으며, 로그아웃 후 기억된 세션이 제거되었습니다.
- hierarchy에 배치한 패널을 `TormiaMain`에 저장한 뒤 Unity Console 오류가 0건이고 EditMode 53/53, PlayMode 34/34가 통과했습니다.
