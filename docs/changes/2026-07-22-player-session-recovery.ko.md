# 플레이어 세션 및 계정 UI 복구

## 요약

- **결정:** 복구 체크포인트에서 중단된 플레이어/계정 UI 작업을 이어서
  기존 멀티플레이 표현 경로를 활성화합니다.
- **상태:** 구현 및 검증 완료.
- **범위:** Unity 표현, 런타임 의도 전송, 계정 세션 데이터.

## 데이터 소유권

캐릭터 외형과 프로필 관계는 계속 계정 소유 데이터입니다. 런타임 이동 샘플과
presence는 Authority의 휘발성 메시지로 유지합니다. 샘플 `Ontology_Player`는
canonical `Player` 엔티티에 Creature, 아이템, 스킬 작성 데이터를 계속
기여하지만 두 번째 애니메이션 어댑터와 액터 프로필 동기화기는 더 이상
소유하지 않습니다.

## 씬 구성

- 계정/월드 입장 후 런타임 플레이어 의도 전송을 활성화했습니다.
- 원격 아바타 복제를 활성화하고 실시간 클라이언트, 전용 `RemoteAvatars`
  루트, 아바타 프리팹, Animator 소스, 캐릭터 파츠 DB를 연결했습니다.
- 계정 입장 흐름에 Authority 클라이언트, 의도 전송기, 로컬 아바타 ID,
  캐릭터 파츠 어댑터 참조를 직렬화했습니다.

## 검증

| 경우 | 기대 결과 | 근거 |
| --- | --- | --- |
| 의도/복제 활성화 | 입장한 로컬 아바타는 휘발성 이동을 전송하고 원격 projection을 표현 | `TormiaMain` 직렬화 플래그와 바인딩 |
| 미연결/미입장 | 프레임별 영속 월드 Fact를 생성하지 않음 | 전송기/표현기의 준비 상태 게이트 |
| 계정 입장 | 아바타 등록 후 저장 외형 적용 | Play Mode에서 선택 월드 입장 상태 확인 |
| 중복 Player 기여자 | 샘플 작성 Fact는 유지하고 중복 런타임 어댑터는 제거 | 라이브 씬 컴포넌트 감사 |
| 회귀 | Core/UI/씬 동작 유지 | EditMode 52/52, PlayMode 32/32 |

클라이언트 간 보간을 눈으로 확인하려면 독립 Unity 클라이언트 두 개가 필요합니다.
이번 실행에서는 로컬 Authority 등록, 입장, 전송 구성, 서버 상태까지 검증했습니다.
